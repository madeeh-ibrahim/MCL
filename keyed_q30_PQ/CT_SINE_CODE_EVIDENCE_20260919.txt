=== 4. Prototype of a source-level remedy (scratch only — the pinned sidecar is unchanged) ===
An optimizer value barrier on the mask ( __asm__("" : "+r"(a)) ), as used by constant-time libraries, keeps the mask opaque,
so no select is formed. Emitted x86-64 -O2 code: one unconditional load per iteration, one branch (the public loop counter):
_sin_ct_barrier:                        ## @sin_ct_barrier
	pushq	%rbp
	movq	%rsp, %rbp
	shrl	$16, %esi
	xorl	%ecx, %ecx
	xorl	%eax, %eax
	.p2align	4, 0x90
LBB0_1:                                 ## =>This Inner Loop Header: Depth=1
	movl	(%rdi,%rcx,4), %edx
	movl	%esi, %r8d
	xorl	%ecx, %r8d
	decl	%r8d
	sarl	$31, %r8d
	andl	%edx, %r8d
	orl	%r8d, %eax
	incq	%rcx
	cmpq	$65536, %rcx                    ## imm = 0x10000
	jne	LBB0_1
	popq	%rbp
	retq
Functional check of the prototype: all 65,536 indices return lut[idx] (arm64 native run). arm64 output keeps the same shape.
Adopting it is an ENGINE change (sidecar v1.0.6 -> next), to be ordered by the author; outputs would stay byte-identical
because the barrier does not change any computed value.

=== 5. What this record establishes, and what it does not ===
ESTABLISHES  (a) arm64 / Apple clang 16.0.0 at -O2, -O3, -Os: the CT build emits no secret-indexed load and no secret-dependent
                 branch in the sine evaluator; output byte-identical to the default build.
             (b) x86-64 / Apple clang 16.0.0 at -O2, -O3: the CT build, as compiled, reads the table only at the secret index
                 behind a secret-dependent branch. On that target the opt-in build does NOT close the cache-timing surface.
DOES NOT     - any other compiler (GCC, MSVC, other clang versions) or target (Cortex-M, RISC-V): not inspected;
ESTABLISH    - timing behaviour measured on hardware: no statistical timing test exists for any target;
             - anything about power/EM leakage (see RESULTS.txt and RESULTS_MULTI_20260919.txt: modeled CPA, leakage present);
             - the cascade path (mcl_cascade_q30 still uses the core fast LUT) and N-2 (data-dependent gcd at key set-up).
CONSEQUENCE  Statements of the form "closed by an opt-in constant-time sine build" are supported for the arm64 build inspected
             here and are NOT supported for x86-64 builds with this compiler until the remedy of section 4 (or an equivalent)
             is adopted and its machine code re-inspected per target.
