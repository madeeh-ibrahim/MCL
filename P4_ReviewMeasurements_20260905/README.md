## Why version 2

v1 derived the twelve coupling weights from a fixed public constant, so the map F was the same for every input. Against a fixed 128-bit map a Hellman / distinguished-point precomputation (W₀ chain points, M stored distinguished points) lets an online walk of N steps jump ahead with probability ≈ (1−ε)·N·W₀/2¹²⁸ — ≈ 2⁻¹⁰ at N = 2⁴⁰, W₀ = 2⁸⁰ — against the W₀/(ε·2¹²⁸) ≈ 2⁻⁴⁶ the v1 conjecture stated. `p4_tmto_toy.py` reproduces the gap on a random 32-bit mapping (measured 2.27e-2 vs the v1 term 7.3e-6). v2 derives the weights from **h = SHA-256(x)** through the sidecar's audited `mcl_t4_q30_params_from_key(h, 0)` (label "MCL-T4-Q30-v1", range [2, 2³⁰), p≠q rule, seed-reachable-symmetry re-draw), so every input evaluates its own map F_x; the initial state is unchanged, the output tag is `MCL-VDF128-T4-v2-out`, the per-iteration cost is identical.
